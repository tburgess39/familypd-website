16.1 • Edition and hardware fit

Compare architecture, edition, licensing, supported upgrade path, drivers, storage, firmware mode, and security requirements before committing. Windows Pro offers management capabilities absent from Home, such as AD domain join. Enterprise or Education availability depends on the organization’s license. Use vendor checks for the exact target version.

16.2 • Installation paths and boot media

An in-place upgrade can preserve supported apps and data; a clean install starts fresh and requires a restore or migration plan. A repair installation can address system components on supported paths. Boot options include approved USB, recovery media, or PXE network deployment. Unattended installs use configuration files or deployment services to standardize choices. Verify media authenticity and keep secrets out of answer files.

Study tip. Separate compatibility, retention, and rollback decisions.

16.3 • Partitions and verification

Check whether a target uses UEFI with GPT or a legacy boot configuration. Confirm the exact disk before partition work, especially with multiple drives attached. Plan recovery keys and data restore before any destructive step. After installation verify activation, updates, drivers, network access, application behavior, policy, and a documented rollback decision.

Choose a recovery route

For an in-place upgrade pilot, record OS build, firmware mode, disk layout, encryption and recovery-key availability, installer source, and driver versions. The acceptance criteria are a successful sign-in, printer test, driver-dependent app workflow, and repeated restart. If any required check fails inside the window, stop the rollout and use the approved recovery route.

Explanation

An in-place upgrade preserves supported apps and data on that upgrade path.

Disk numbering alone does not establish which disk holds protected data.
