Checkpoint 1

Start with the troubleshooting process

Hardware troubleshooting is not “swap parts until it works.” A good technician narrows the problem using evidence.

1. IdentifySymptoms, scope, recent changes
2. TheoryMost likely cause first
3. TestProve or reject the theory
4. FixPlan and implement safely
5–6. Verify + DocumentFull function, prevention, ticket notes
Memory trick: SEE → THINK → TEST → FIX → VERIFY → WRITE. Never skip from “I see a symptom” straight to “replace a part.”

Checkpoint 2

Find the stage where the computer stops

A symptom becomes easier to troubleshoot when you identify how far the system gets.

Power → POST → Firmware → Boot device → OS

Think of startup as a chain. If the chain breaks early, later steps cannot happen.

No powerNo POSTNo boot deviceOS crash

Display is a separate clue

A computer can be running while the display path fails. Check monitor power, source/input, cable, GPU/port, and display settings before assuming the whole PC is dead.

Checkpoint 3

BIOS/UEFI is part of the diagnosis

Firmware settings can decide what boots, which devices are available, how fans behave, and which security features are active.

TECHWORKS UEFI DIAGNOSTIC

Boot mode: UEFI
Boot #1: Windows Boot Manager
USB ports: Enabled
Secure Boot: Enabled
TPM: Enabled
CPU temp: 41°C
Fan profile: Balanced

Firmware settings you should recognize

Boot orderFixed disk, optical, USB, or network/PXE can be prioritized.
USB permissionsControllers, ports, or individual devices may be enabled/disabled.
Fan controlsFirmware may balance acoustics, power, temperature, and performance.
SecurityAdministrator/system passwords, Secure Boot, and TPM settings may be present.
Know the difference: Secure Boot checks trusted digital signatures during startup. A TPM is hardware-backed storage for cryptographic secrets and measurements. A BIOS/UEFI password restricts firmware or system access.

Checkpoint 4

Power and POST: trace the path

For a no-power or no-POST ticket, verify simple external causes before replacing internal components.

Power path

Outlet → power cable → PSU → motherboard/components.

A PSU tester can help verify power-supply output. Check cables and recent hardware changes before declaring a board or CPU dead.

POST clues

POST problems can involve loose power/data connections, RAM or expansion-card seating, a faulty PSU, CPU/firmware issues, or vendor-specific beep/diagnostic codes.

Hardware safety: Shut down, unplug AC power, and use ESD precautions before reseating components. Never open a power-supply enclosure; capacitors can retain dangerous charge. Test the PSU externally with appropriate tools or replace it as a unit.
No-power ticket

The user says, “Nothing happens when I press the power button.”

Checkpoint 5

Storage and boot problems leave clues

A missing or failing drive can show up before the OS, inside the OS, or through performance/reliability symptoms.

Availability

Boot device not found, missing drive in the OS, read/write failures, drive/activity LEDs, unusual mechanical noise, or alarms can point to storage trouble.

Reliability

S.M.A.R.T. data can report drive health indicators. Bad sectors and growing error counts are warnings; protect data before experimenting.

Performance

IOPS describes input/output operations per second. A slow system is not automatically a bad drive—rule out heat, memory pressure, software, and other bottlenecks.

Storage diagnostic

Ticket: The NVMe drive appears in UEFI, but Windows will not start.

Which evidence is most useful next?

RAID warning: A controller alert or failed member does not mean “initialize the array.” Identify the RAID level, failed device, controller status, and backup state first. A wrong rebuild action can make recovery harder.

Checkpoint 6

Heat and physical symptoms are evidence

Component failures are not always invisible. Inspect before you assume.

OverheatingCheck temperature sensors, CPU/case fans, heat sink contact, airflow, dust, blanking plates, and ambient temperature.
Physical damageLook for liquid damage, scorch marks, swollen capacitors, broken connectors, dirt, and signs of ESD/power events.
PerformanceVerify the complaint. Rule out software/network causes and misconfiguration before replacing hardware.
Date/time resetsA weak RTC/CMOS battery can cause persistent time/configuration loss on systems that use one; CR2032 is common.
Pattern recognition

A PC works for 15–20 minutes, then slows dramatically and sometimes shuts down.

Checkpoint 7

Display problem or system problem?

Separate “the computer is not working” from “I cannot see what the computer is doing.”

No image

Check display power, cable condition, correct input/source, correct GPU/port, and whether the system itself reached POST. For projectors, overheating and lamp/bulb failure can also remove the image.

Poor image

Dim/fuzzy image, flicker, dead pixels, burn-in/image retention, or incorrect color may involve cable/port quality, display settings, calibration, panel damage, or the display itself.

Display triage

The desktop powers on and POST beeps normally, but the monitor shows “No Signal.”

Checkpoint 8

Final support queue

Use the symptom, evidence, and recent changes. Choose the best next technician action—not the most expensive action.
