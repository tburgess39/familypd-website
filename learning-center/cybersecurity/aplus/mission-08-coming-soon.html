8.1 • Hypervisors

Type 1

Runs directly on hardware. Think bare metal.

Type 2

Runs as an application on top of a host operating system.

Memory: Type 1 touches hardware first; Type 2 has an OS underneath it.

Why virtualize?

  • Sandboxing and safe labs
  • Legacy operating systems
  • Cross-platform testing
  • Training environments
  • Server consolidation
  • Virtual desktops
  • Application containers

Virtualization resource checklist

ResourceQuestion to ask
CPUDoes the processor support virtualization extensions, and are they enabled in BIOS/UEFI?
MemoryCan the host provide enough RAM for itself plus each guest?
StorageIs there enough physical storage for virtual disks and snapshots?
NetworkingDo VMs need host-only, VM-to-VM, or access to the physical network?
Security: secure the guest OS, the host OS, and the hypervisor. A host failure can take every VM on that host offline.

8.2 • Cloud concepts

ConceptPlain language
High availabilityDesign for minimal downtime.
ScalabilityIncrease or decrease resources as demand changes.
ElasticityResources expand/contract dynamically without disrupting service.
Shared resourcesProvider infrastructure can serve multiple workloads/customers.

Service models

ModelYou are mainly consuming

SaaSA finished application running in the cloud.
DaaSA cloud-hosted desktop environment.
Check: You need a finished email application, not servers to manage. Which model?

SaaS.

Check: You need virtual servers and networking that your team will configure. Which model?

IaaS.
